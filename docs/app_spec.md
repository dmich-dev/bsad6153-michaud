# Model catalogue: what this site must answer

DJ is choosing a model for a coding task or a tool-using homelab agent. A visitor should be able to make a shortlist without knowing SQL, find out when the listings were checked, and see what the catalogue cannot tell them. The Week 1 baseline records a model-selection decision but no timed duration. Do not claim this site saved time or that a model will catch bugs in someone’s code.

1. **Which stored text models have advertised tool use, at least 128,000 tokens of context and the lowest listed base-token cost?** Start with M2 Q1 / golden Q01. Show the catalogue ID, advertised context, per-million input/output rates and the example cost of 1M input plus 250k output tokens, across requests. Explain the example; unknown rates are not free. A filter should change the query itself.
2. **For a model on that shortlist, which of the provider routes we actually collected advertise tools, and what limits and prices do those routes list?** Start with M2 Q2 / golden Q02. Bind the selected model ID as a SQL parameter. An empty result means no matching route in our sample, not that a model has no providers. These are metadata comparisons, not coding benchmarks, all-in rates or promises of availability.

**Trust and freshness.** Put the last successful `sync_runs.finished_at`, its timezone and age above the results. Warn after 24 hours, the Milestone 3 target, or if there has never been a successful sync. A new sync check is not a new observation for every model. Use `st.cache_data` with a five-minute TTL, well below the daily sync interval. Evaluate age from the stored timestamp at display time, not from a cached color or flag.

**Data boundary.** Read only `APP_DATABASE_URL`, require the verified reader role `app_reader`, a read-only transaction, verified TLS, and bound queries. Do not load the admin connection, send model prompts, write records, expose connection strings, stack traces, private usage logs, raw source records or arbitrary SQL. Show only authorized public model/provider metadata with OpenRouter attribution. Provide a short About note, sample coverage limits, and the Render free-tier cold-start notice. No paid LLM or sign-in is needed for public visitors.

**Acceptance.** Both views run on the real database. Unknown values, empty filters, no successful sync, stale data and connection failure each have plain-language states. Verify three displayed numbers against independent SQL; document the role and a safely denied write. Keep a line-numbered code tour and let the student personally check it. A local or private deployment is not the public Render URL. Gate future publication separately from local verification.
