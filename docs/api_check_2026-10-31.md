## 1. Access: how does a request identify us?

The [authentication guide](https://openrouter.ai/docs/api_reference/authentication) documents an API key
sent in the `Authorization` header as a Bearer token. Our catalog research requests succeeded without a
key, while the [catalog reference](https://openrouter.ai/docs/api/api-reference/models/list-all-models-and-their-properties)
marks authentication as required. Treat anonymous catalog access as observed behavior, not a promise
that every route is public. The future importer can read an optional key locally and stop clearly on an
authentication error.

**DJ's source check/correction:** Pending.

## 2. Pages: how do we get all the records?

The [catalog reference](https://openrouter.ai/docs/api/api-reference/models/list-all-models-and-their-properties)
documents `limit` and `offset`, pagination links, and a total count. Plan: request 100 records per page,
follow valid `links.next` URLs, and stop at the end. Keep `output_modalities=all` on every page because
the default text-output catalog was below 500 records in our research. Report distinct catalog IDs and
canonical identities separately; do not repeat records to reach the threshold.

**DJ's source check/correction:** Pending.

## 3. Slow down: what if the service says we are requesting too quickly?

The [limits guide](https://openrouter.ai/docs/api_reference/limits) says to retry 429 responses with
exponential backoff and honor `Retry-After` when present. Proposed project policy: sequential requests,
at least one second apart, with bounded retries. A specific public-catalog quota was not established;
free-model inference quotas are not catalog quotas.
