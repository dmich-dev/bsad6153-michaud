2. **What would make me trust a system's recommendation? What would make me ignore it?** I mainly
   use OpenAI's 6.1 Sol because I find it cost-effective and it connects well with HERMES. A useful
   recommendation should explain how a model fits the actual task and that workflow, show its source
   and retrieval date, and make the price units and limitations clear. Stale examples, unsupported
   capability claims, or a recommendation that overlooks HERMES compatibility would make it less
   useful to me. Catalog metadata can narrow the options; it cannot by itself prove coding quality.

3. **What a system should never do on my behalf without asking:** Routine work should follow the
   permissions I already gave it. It should ask before buying credits or changing paid plans, sending
   messages, submitting coursework, or deleting important data. A model recommendation should not
   automatically expand a bot's server permissions. These are proposed boundaries for this project,
   rather than a claim that every routine action needs a new approval.

4. **How I would know it was actually helping:** I would compare how long model selection takes and
   whether the resulting coding or homelab task finishes correctly with an appropriate cost. I would
   also track stalled or repeated bot loops, corrective retries, and how much intervention I need to
   provide. Faster selection is useful only if task quality and reliability remain acceptable. These
   are proposed measures; this project has not yet established timed baseline results or measured savings.

   records show repeated Sol use across several kinds of work. A question worth testing is whether
